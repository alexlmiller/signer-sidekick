# Signer Sidekick v2.3.1

- **Automatic rewards recover:** temporary node/API failures, wallet contention and actions already
  completed by another caller no longer disable the schedule. Hard refusals and uncertain
  transactions still require operator review.
- **Security fixes:** updated server, validation and wallet dependencies, with regression checks for
  authentication, validation limits and wallet-code isolation. One advisory remains in unloaded
  optional wallet dependencies, tracked in [#65](https://github.com/alexlmiller/signer-sidekick/issues/65).
- **New image location:** releases now publish under `ghcr.io/alexlmiller/signer-sidekick`.

## Upgrade

Follow [Operations](https://github.com/alexlmiller/signer-sidekick/blob/v2.3.1/docs/operator/operations.md#upgrade),
including the database, gas-wallet key and configuration backup. Select the v2.3.1 checkout and set:

```dotenv
SIDEKICK_IMAGE_REPOSITORY=ghcr.io/alexlmiller/signer-sidekick
SIDEKICK_IMAGE_TAG=2.3.1
```

Schema 45 adds preparation failure classification; financial rows are not rewritten. Older images
require a compatible database for rollback. Previously stopped schedules remain off: review the
reason before explicitly re-enabling automatic runs.
